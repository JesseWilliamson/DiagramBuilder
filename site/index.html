Diagrams that move with your algorithm

dsviz turns the state of a data structure into an SVG diagram, then animates it as the state changes.

0 dependencies3 themeskeyed tweeningMotion-ready
How it works

State in, scene out, renderer animates the difference

Every diagram is a pure function from your algorithm's state to a Scene: a flat, ordered list of plain objects (circles, rects, text, arrows), each with a stable id. Layout helpers like array() and binaryTree() are just functions that build those lists for you.

The renderer diffs the new scene against what's on screen by id. Same id means "this is the same thing, it moved", so it tweens. New ids fade in, missing ids fade out. That one rule is all the animation system there is. React's key and Motion's layoutId work the same way, which is why a Motion renderer can sit on top with no changes.

Quick start

One array, one pointer, one slider

A layout returns its nodes plus anchor helpers like arr.top(i), so other pieces can attach to it without doing coordinate math. The pointer has a fixed id ('i'), so dragging the slider slides it instead of redrawing it.

Stepping through an algorithm

Binary search, frame by frame

Write the algorithm as a normal generator that yields a snapshot whenever something interesting happens. createPlayer runs it once, keeps every frame, and gives you next / previous / play / seek. Because frames are stored, scrubbing backwards is just reading an earlier array element.

The snapshot-to-scene function is pure, so step 4 always looks the same however you got there. Try changing the target, or make mid round up and watch what changes.

Identity

Keys decide what moves

By default an array cell's id is its index. When bubble sort swaps a[2] and a[3], cell 2 is still cell 2; only its number changes. Give each element a stable key (here, its original position) and the same swap becomes two boxes sliding past each other.

Turn stable keys off mid-sort to see the difference. The index labels underneath never move either way: an index belongs to a slot, a value belongs to an element.

Pointers

Reversing a linked list

linkedList() draws whatever your next pointers say, including the half-reversed state where the list is in two pieces. Each arrow's id comes from the node it leaves, so flipping curr.next swings that arrow around instead of deleting it. Arrows that point backwards curve underneath.

Note the explicit order: by default boxes are placed by walking from the head, which would rearrange them as soon as the list is broken. Pinning the order keeps every box still so you only watch the pointers.

Trees

Binary search tree: insert and search

The tree is your own plain object; dsviz only lays it out. Placing each node at its in-order position means the tree reads left-to-right in sorted order. New nodes grow out of their parent because the layout sets each node's enter position to the parent's.

Click any node to trace the search path to it. This demo animates with setTimeout instead of a player, to show you don't need one.

Graphs

BFS and DFS, on a graph you can drag

Node positions are ordinary state. Dragging writes the new position into pos and re-renders with duration: 0, so the node follows the pointer while edges recompute around it. Because each frame of the traversal is pure, you can drag mid-animation and nothing breaks.

The frontier underneath is an array whose keys are push counters, not node names. DFS can push the same node twice, and duplicate ids are the most common keyed-rendering bug (dsviz warns about it in the console). Click a node to start from there.

Dynamic programming

Filling an LCS table

The longest common subsequence of two strings. Each cell dp[i][j] is the LCS length of the first i letters of A and the first j letters of B. Arrows show which earlier cells the current one reads from. Their ids are fixed (dep0, dep1), so they glide along with the cursor.

After the table fills, the traceback walks from the bottom-right corner back to the start and spells out one LCS.

React + Motion

Using framer-motion instead of the built-in renderer

The layouts don't know how they'll be drawn. In a React app, skip createView and map scene nodes to motion elements, using each node's id as the React key. AnimatePresence handles enter and exit; springs handle everything else.

Two details matter. On motion SVG elements, x and y are CSS transforms, so the SVG attributes are animated as attrX/attrY. And a straight path can't morph into a curved one by string interpolation, so arrows spring their numbers and rebuild the path each frame with dsviz's own arrowPath(). The full adapter is in examples/react-motion.tsx.

// examples/react-motion.tsx (excerpt)
import { AnimatePresence, motion, useSpring, useTransform } from 'motion/react';
import { arrowPath, bounds, classFor } from 'dsviz';

export function DiagramSVG({ scene, padding = 24 }) {
  const b = bounds(scene);
  const viewBox = `${b.x - padding} ${b.y - padding} ${b.w + 2 * padding} ${b.h + 2 * padding}`;
  return (
    <motion.svg className="dv-root" initial={false} animate={{ viewBox }}>
      <AnimatePresence initial={false}>
        {scene.nodes.map((n) => <MotionNode key={n.id} node={n} />)}
      </AnimatePresence>
    </motion.svg>
  );
}

function MotionArrow({ n }) {
  const x1 = useSpring(n.x1), y1 = useSpring(n.y1), x2 = useSpring(n.x2), y2 = useSpring(n.y2);
  const bend = useSpring(n.bend ?? 0);
  useEffect(() => { x1.set(n.x1); y1.set(n.y1); x2.set(n.x2); y2.set(n.y2); bend.set(n.bend ?? 0); });
  const d = useTransform([x1, y1, x2, y2, bend], ([a, b, c, e, k]) =>
    arrowPath({ x: a, y: b }, { x: c, y: e }, k, n.head ?? true, n.width ?? 2));
  return <motion.path className={classFor(n)} d={d} exit={{ opacity: 0 }} />;
}

// In a component:
const arr = array(a, { tones: { [mid]: 'active' } });
return <DiagramSVG scene={combine(arr.window(lo, hi), arr, pointer({ id: 'mid', at: arr.top(mid), label: 'mid' }))} />;

Tones are classes. tone: 'active' becomes dv-tone-active. Colours live in CSS variables on .dv-root, so restyling and dark mode need no JS, and colour changes animate with plain CSS transitions.

Interrupts are smooth. Each render tweens from what's currently on screen, not from the last target, so clicking Next mid-animation never snaps.

Reduced motion. If the viewer prefers reduced motion, every render is instant.

Make it yours

Exercises, roughly in order of difficulty

  1. Make your own theme. Copy the .dv-theme-brilliant block in styles.ts, rename it, and give it a Theme object in themes.ts. Try a chalkboard theme: dark green surface, white strokes, a handwritten Google font.
  2. Add a dv-tone-warning tone. Pure CSS. Find where tones are defined in styles.ts and why one selector covers both rects and circles.
  3. Write a heap() layout. Take a plain array, build the implicit tree (children of i are 2i+1 and 2i+2) and reuse binaryTree(). Then draw the array underneath with matching tones. Keys matter: what should a node's key be so sift-down animates as swaps?
  4. Animate BST deletion. The two-child case replaces a node with its in-order successor. Decide which ids should survive so the successor visibly travels up.
  5. Replace the in-order tree layout with Reingold–Tilford. The current layout is wide because every node gets its own column. Keep the same TreeDiagram return type so nothing else changes.
  6. Hash table. Compose array() for buckets with one linkedList() per chain, positioned with each bucket's bottom(i) anchor.
  7. Text crossfade. When a text node's string changes, the renderer swaps it instantly. Change render.ts to fade the old string out and the new one in. Hint: you'll need a second element for the outgoing text.
